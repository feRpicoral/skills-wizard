# Ignoring files and code

Use `.prettierignore` to skip whole files or directories, and `prettier-ignore` comments to skip parts of a file.

## .prettierignore

Put it at the project root. It uses gitignore syntax:

```text
# Ignore artifacts:
build
coverage

# Ignore all HTML files:
**/*.html
```

The docs recommend always having one, so `prettier --write .` formats everything you want without touching generated files, and editors know what not to format.

## What is ignored by default

- Version control directories: `.git`, `.jj`, `.sl`, `.svn`, `.hg`.
- `node_modules`, unless `--with-node-modules` is passed.
- Patterns in `.gitignore`, when it is in the directory Prettier runs from (since 3.0). Committed generated code is not in `.gitignore`, so it needs its own `.prettierignore` entry.

## --ignore-path

By default the CLI reads `./.gitignore` and `./.prettierignore`, relative to the working directory. `--ignore-path <file>` replaces those defaults; to add a file and keep both, pass all three:

```bash
prettier . --check --ignore-path=.gitignore --ignore-path=.prettierignore --ignore-path=extra-ignore
```

Running Prettier from a subdirectory reads that directory's ignore files, not the root's.

## prettier-ignore comments

| Language               | Syntax                                                                                 | Scope                                                  |
| ---------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| JavaScript, TypeScript | `// prettier-ignore`                                                                   | The next node in the syntax tree                       |
| JSX                    | `{/* prettier-ignore */}`                                                              | The next element                                       |
| HTML                   | `<!-- prettier-ignore -->`                                                             | The next element                                       |
| HTML attributes        | `<!-- prettier-ignore-attribute -->` or `<!-- prettier-ignore-attribute (mouseup) -->` | All attributes, or the named ones, of the next element |
| CSS, SCSS, Less        | `/* prettier-ignore */`                                                                | The next rule or declaration                           |
| Markdown               | `<!-- prettier-ignore -->`                                                             | The next block (paragraph, table, list)                |
| Markdown range         | `<!-- prettier-ignore-start -->` ... `<!-- prettier-ignore-end -->`                    | Everything between, top level only                     |
| YAML                   | `# prettier-ignore` on the line above                                                  | The next node                                          |
| GraphQL                | `# prettier-ignore`                                                                    | The next node                                          |
| Handlebars             | `{{! prettier-ignore }}`                                                               | The next element                                       |

```js
// prettier-ignore
matrix(
  1, 0, 0,
  0, 1, 0,
  0, 0, 1,
);
```

Markdown table kept exactly as written:

```markdown
<!-- prettier-ignore -->
| Runner  |  req/s |
|:--------|-------:|
| fastify | 48,210 |
```

Range ignores are meant for auto-generated sections (tables of contents, contributor lists) and need a blank line before each marker:

```markdown
Text above.

<!-- prettier-ignore-start -->
<!-- SOMETHING AUTO-GENERATED BY TOOLS - START -->

| MY | AWESOME | AUTO-GENERATED | TABLE |
|-|-|-|-|
| a | b | c | d |

<!-- SOMETHING AUTO-GENERATED BY TOOLS - END -->
<!-- prettier-ignore-end -->
```

## Pragmas

- `--require-pragma` (`requirePragma`): format only files that start with a `@prettier` or `@format` docblock.
- `--check-ignore-pragma` (`checkIgnorePragma`, 3.6.0+): skip files that start with a `@noprettier` or `@noformat` docblock. Useful for single generated files without editing `.prettierignore`.

## One-off exclusions on the CLI

```bash
prettier . "!**/*.{js,jsx,vue}" --write
```

Negative patterns exclude files for one command without touching `.prettierignore`.

## Recipes

- Committed generated code (GraphQL or OpenAPI clients, Prisma output): add the directory to `.prettierignore` (`src/generated`, or `**/generated` for every package). Also add it to ESLint's global ignores so lint rules skip it.
- Generated code that is gitignored: already skipped when Prettier runs from the root.
- One hand-formatted table or block in a Markdown file: `<!-- prettier-ignore -->` directly above it. Ignoring all `*.md` files or the whole file is broader than the request.
- A file type the project is not ready to format yet: add `*.html` (or similar) to `.prettierignore`, as the install docs suggest.
- Lockfiles and build output: list them if they are not gitignored (`yarn.lock`, `package-lock.json`, `pnpm-lock.yaml`, `dist`, `build`, `coverage`).

## Checking what is ignored

Run `npx prettier --check .` before and after the change. The ignored files should no longer be listed, and everything else should still be checked.
