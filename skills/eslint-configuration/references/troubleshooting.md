# Troubleshooting

## Tools, in the order to try them

1. `npx eslint --print-config path/to/file.ts`: the computed config for one file (rules, language options, plugins). It does not show `files`, `ignores` or `name`, but it does show ESLint's own defaults. Use it when a rule seems not to apply or the wrong language options are used.
2. `npx eslint --debug path/to/file.ts`: verbose output; search it for `eslint.config` to see which config file loaded. Use it when several config files exist.
3. `npx eslint --inspect-config`: starts `@eslint/config-inspector`, a browser UI that shows which config objects match a file name, deprecated rules and rule counts. It is interactive, so ask before running it in an agent session.

If none of this explains the problem, update `eslint` and the related plugins and shareable configs to their latest versions, then ask in https://eslint.org/chat/help.

## Symptoms

| Symptom                                                                                                                                                                                                                                  | Cause and fix                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `A config object is using the "env" key, which is not supported in flat config system.` (also `extends`, `globals`, `ignorePatterns`, `noInlineConfig`, `overrides`, `parser`, `parserOptions`, `reportUnusedDisableDirectives`, `root`) | An eslintrc-style key in a flat config object. Translate it (`env`/`globals`/`parser`/`parserOptions` move under `languageOptions`, `ignorePatterns` becomes `globalIgnores([...])`, `overrides` becomes later `files`-scoped objects). For `extends`, wrap the array in `defineConfig()`. If the key comes from a plugin's config, upgrade the plugin or wrap that config with `FlatCompat`. |
| `TypeError: context.getScope is not a function` (or `getAncestors`, `markVariableAsUsed`, `getDeclaredVariables`)                                                                                                                        | A plugin written for the pre-9 rule API. Upgrade it; if the latest version still fails, patch it with the `@eslint/compat` utilities and open an issue on the plugin.                                                                                                                                                                                                                         |
| A plugin fails on `context.getFilename`, `getSourceCode`, `getCwd`, `getPhysicalFilename`, `parserOptions` or `parserPath` after upgrading to ESLint 10                                                                                  | These were removed in 10.0.0. Upgrade the plugin or stay on ESLint 9 until it supports 10.                                                                                                                                                                                                                                                                                                    |
| `ESLintCircularFixesWarning: Circular fixes detected while fixing path/to/file. It is likely that you have conflicting rules in your configuration.`                                                                                     | Two fixable rules undo each other across fix passes. In an editor that applies single fixes (VS Code: "Fix this (rule-name) problem"), apply one fix and see which new problem appears; that is the other rule. Remove or reconfigure one of them. A stylistic core rule fighting `prettier/prettier` is the classic case.                                                                    |
| `File ignored because of a matching ignore pattern. Use "--no-ignore" ... or use "--no-warn-ignored" to suppress this warning.`                                                                                                          | The file was passed explicitly (often by lint-staged) and matches an ignore. Keep the ignore; add `--no-warn-ignored` if `--max-warnings 0` turns it into a failure.                                                                                                                                                                                                                          |
| `/* eslint-env */ comments are no longer supported`                                                                                                                                                                                      | ESLint 10 reports them. Delete the comment and declare the globals in the config.                                                                                                                                                                                                                                                                                                             |
| `There are suppressions left that do not occur anymore. Consider re-running the command with --prune-suppressions.` (exit code 2)                                                                                                        | Suppressed violations were fixed. Run `npx eslint --prune-suppressions` and commit the updated `eslint-suppressions.json`.                                                                                                                                                                                                                                                                    |
| `.ts`, `.vue` or other files are not linted, or ESLint says a file was ignored because no configuration matched                                                                                                                          | Only `**/*.{js,mjs,cjs}` are linted by default. Add a `files` pattern for the extension (often provided by the shared config, such as typescript-eslint).                                                                                                                                                                                                                                     |
| A rule or language option does not apply to some files                                                                                                                                                                                   | Check with `--print-config <file>`. Usual causes: the `files` pattern is relative to a different directory than assumed, a later object overrides it, the plugin is registered in an object whose `files` do not match, or (ESLint 10) a nested `eslint.config.*` closer to the file is used instead.                                                                                         |
| `ignores` has no effect                                                                                                                                                                                                                  | The object has other keys, so the ignores are non-global and only match files. Use `globalIgnores()`, or `dir/**` for non-global ignores.                                                                                                                                                                                                                                                     |
| Something inside an ignored directory cannot be unignored                                                                                                                                                                                | `dir/**` stops traversal. Use `dir/**/*` with `!dir/keep.js` patterns so ESLint still enters `dir/`.                                                                                                                                                                                                                                                                                          |
| New errors right after upgrading to ESLint 10                                                                                                                                                                                            | New `eslint:recommended` rules (`no-unassigned-vars`, `no-useless-assignment`, `preserve-caught-error`), JSX reference tracking, `globalThis` in `no-shadow-restricted-names`, or `eslint-env` comments. Fix the code; do not blanket-disable the rules.                                                                                                                                      |
| New errors after upgrading a plugin, on lines with `eslint-disable`                                                                                                                                                                      | `reportUnusedDisableDirectives` (default `"warn"`) flags disable comments that a fixed false positive made unused. Delete the comment.                                                                                                                                                                                                                                                        |
| Lint results differ between runs or machines                                                                                                                                                                                             | Stale `--cache` results for type-aware or import rules, different ESLint or plugin versions (run the version check), or different working directories with ESLint 9 lookup.                                                                                                                                                                                                                   |
| No colors in CI output after upgrading to ESLint 10                                                                                                                                                                                      | The `stylish` formatter honors `NO_COLOR` and `NODE_DISABLE_COLORS`. Use `--color` to force colors.                                                                                                                                                                                                                                                                                           |
| VS Code ignores `eslint.config.*`                                                                                                                                                                                                        | The ESLint extension supports flat config by default from 3.0.10. Update it, or set `"eslint.experimental.useFlatConfig": true` for older versions.                                                                                                                                                                                                                                           |

## Format on save fights the linter

The editor formats with Prettier, then ESLint's fix-on-save applies a stylistic rule that disagrees (or the reverse), so the file flips on every save. ESLint itself may print the circular fixes warning.

1. Find the conflicting rules: `npx eslint-config-prettier path/to/file.ts` (eslint-config-prettier's CLI helper; exit code 2 means conflicts were found).
2. Remove those stylistic rules from the config, and make sure `eslint-config-prettier` (or `eslint-plugin-prettier/recommended`, which includes it) comes after every shared config that enables formatting rules. Core formatting rules such as `indent`, `quotes`, `semi` and `comma-dangle` are deprecated since 8.53.0 and marked available until 11.0.0 in their rule metadata, so there is no reason to keep them next to Prettier.
3. Make the editor use the project's local Prettier and ESLint versions so its output matches the CLI.
4. Re-run `npx eslint .` and `npx prettier --check .`.

The prettier-configuration skill covers the Prettier side in more detail.
